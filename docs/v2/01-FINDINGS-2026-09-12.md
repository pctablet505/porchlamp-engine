# Findings — audit of the CVI handoff and live data (2026-09-12)

Tags: **[MEASURED]** = reproduced by a command in §F; **[LIVE]** = checked
against GitHub / deps.dev on 2026-09-12; **[DERIVED]** = arithmetic on
measured values and the code as read; **[CLAIMED]** = from the handoff, not
re-verified here.

## A. State of the deliverable in one paragraph

The scoring engine, API and UI are implemented and tested. The data plane is
not delivering what the engine expects. Of the 18 inputs the composite uses,
four are 100% missing on real data, three are constant across the whole
universe, two are computed from a sample whose time window varies from one day
to seven years, and one (GFI count) is zero on 99.9% of repositories because of
a collector query bug. The served `data/cvi.db` is still the synthetic
1,000-repo catalog, not the verified universe. The ranking that exists today is
therefore a function of roughly six real signals, two of which have a median of
four samples. Fixing the data plane is worth more than any change to the
formula, and the formula also needs the changes in `02-RANKING-DESIGN.md`.

## B. Verified findings

### F1. The served database is the synthetic catalog **[MEASURED]**
`data/cvi.db` holds 1,000 rows with quadrant counts Sweet Spot 350 / Graveyard
250 / Nursery 250 / Crucible 150 and per-ecosystem means within 0.7 of each
other (55.6–56.3). The top-15 by CVI include `async-rs/arena-alloc-lib`,
`go-infra/dns-resolver-lib`, `sys-kernel/boot-loader-client`,
`micrometer-contrib/async-completable-toolkit`: names from
`cvi/benchmark_data.py`. Only 118 distinct CVI values exist across 981
non-gated rows. Anything currently served is fixture data.

### F2. GFI collector returns zero for almost every repository **[LIVE]**
`scripts/gather.py` queries `labels=good-first-issue,help-wanted`. The GitHub
REST `labels` parameter is a conjunction (an issue must carry every listed
label), and GitHub's default labels are `good first issue` / `help wanted`
(spaces). Live counts of open issues:

| Query | microsoft/vscode | pallets/flask (all states) |
|---|---|---|
| `labels=good-first-issue,help-wanted` (current) | 0 | 0 |
| `labels=good first issue` | 18 | 36 |
| `labels=help wanted` | 100 (page cap) | – |

Result in the data: `active_unclaimed_gfis == 0` in 99.9% of 3,762 bundles, so
parameter 5.1 (40% of the accessibility pillar) is a constant 0.

### F3. Dependents are 100% missing because the wrong deps.dev endpoint is used **[LIVE]**
`gather.py` reads `usedByCount` from `GET /v3/projects/github.com%2F{o}%2F{n}`.
That response carries `starsCount`, `forksCount`, `openIssuesCount`, `license`,
`scorecard` and nothing about dependents, so `usedby_count` is always `None`.
`GET /v3alpha/systems/pypi/packages/flask/versions/3.1.0:dependents` returns
`{dependentCount 139, directDependentCount 110, indirectDependentCount 29}`
(per version; package-level aggregation to be measured in packet W1-2).
Consequence **[DERIVED]**: every repo has dependents 0; the ECDF formula counts
`x_k <= x`, so every repo scores percentile 100 on parameter 2.1 (40% of
criticality). The pillar's largest weight is a constant.

### F4. The PR sample is "30 newest PRs", not a time window **[MEASURED]**
`PR_SAMPLE = 30`. Over 3,762 bundles the 30 PRs span (days, q05/q25/q50/q75/q95)
= 1 / 18 / 139 / 924 / 2,553. Ghost rate, merge rate and TTM are therefore
computed over one day of history for busy repos and seven years for quiet ones,
which makes them incomparable across repos. External PRs with a measured
first-response latency: q05 0, q25 1, median 4, q75 9, q95 21. TTFHR (the
single highest-weighted parameter) is a median of about four values for the
median repo.

### F5. "First-timer" and "return rate" are not what the spec defines **[MEASURED]**
`author_prior_merged_commits` is 0 for every external PR in all 3,762 bundles
(never derived). So MR_first is the plain external merge rate. `rr_90` is
derived over the same 30-PR sample as "authors with ≥2 PRs whose gap ≤ 90 d";
it equals 1.0 from q25 to q95 (zero in 6.4%), so parameter 5.2 scores 100 for
about 94% of repos. With F2, the accessibility pillar is ≈ 0.40·0 + 0.35·100 +
0.25·50 = 47.5 for almost everyone.

### F6. The black-hole gate fires on tiny denominators **[MEASURED]**
Recomputing the Stage-0 GR_14 semantics over the bundles: 1,104 / 3,762 (29.3%)
are black holes. 138 of them rest on ≤ 3 open external PRs and 221 on ≤ 5. The
denominator is open external PRs only, and a repo with two stale open PRs that
merged the other 28 is gated. The handoff's "1,283 genuine black holes" is
partly an artefact of sample size and denominator; the corrected number comes
after packet W2-2.

### F7. Three parameters are constants on real data **[MEASURED]**
`ai_posture = AD_HOC` (3,762/3,762), `promotion_ladder = AD_HOC` (3,762/3,762),
`legal_ip_model`: DCO 3,693, FOUNDATION_CLA 41, no CORP_CLA at all (the deriver
defaults to DCO, the best score, when nothing is found). Governance therefore
reduces to `47 + 8.75·EF` and rigor's AI-posture term to a constant 40.
**[DERIVED]** These three carry 18.25 points of the 100-point composite and
contribute zero discrimination.

### F8. Missingness rates per input **[MEASURED]**
dependents_count 100%, dx_ci_minutes 100%, openssf_signals 100%,
monthly_downloads 77.8%, scorecard_score 37.8%, mean_inline_comments 28.9%,
rr_90 5.7%. Missing values enter the engine as 0.0 (worst) for scorecard, GFI
and rr_90 but as neutral 50 for dx and OpenSSF signals (the handoff's Q1).

### F9. Elephant factor is a login proxy **[MEASURED, documented in derive.py]**
Each contributor login is treated as its own organisation, so EF measures
author concentration, not vendor concentration: EF = 1 for 1,906 repos, 2 for
793, 3 for 373, ≥ 4 for 662. Commit author email domains are available from the
same REST endpoint and are not used.

### F10. A fabrication path exists and is documented as the way to build the dataset **[MEASURED]**
`scripts/curate_dataset_llm.py` and `HANDOFF-DATASET-CURATION-AGENT.md` instruct
a local LLM to *generate* stars, downloads, scorecards, PR events and
provenance (`"source": "ecosystem-intelligence"`) and to mark every field
`"verified"`. Anything produced that way would pass `verify.py` (which only
cross-checks stars/forks/license against deps.dev when present). This is the
single most direct way to manipulate the index and violates the owner rule that
only verified data enters SQLite. It must be deleted, and provenance must be
made unforgeable (`03-ANTI-MANIPULATION.md` §5).

### F11. Mirrors and archived repositories are not gated **[LIVE]**
The REST repository object exposes `mirror_url` (`gcc-mirror/gcc` →
`git://gcc.gnu.org/git/gcc.git`) and `archived`; neither is collected. Mirrors
accept no PRs and would be scored as black holes or ghosts instead of routed.

### F12. Bot identity is a substring list **[MEASURED, from constants]**
`"actions"`, `"stale"`, `"claude"` match human logins. GraphQL exposes
`author { __typename }` (`Bot` vs `User`), which is not requested.

### F13. The sweep is in flight **[MEASURED]**
`scripts/run_all.py --all --skip-downloads --db data/cvi.db` (pid 173791,
started 09:08) was at 3,275 / 5,753 with 3,148 CLEAN, 127 FLAG, 0 FAIL when
checked; `data/derived` had 3,762 files. It will promote at the end and
overwrite `data/cvi.db` with engine-v1 scores computed on the inputs above.
Nothing in this plan changes that run; v2 re-derives from `data/raw`.

### F14. The handoff's discrimination claim does not hold **[DERIVED]**
"CVI stdev 31.9 on 3,170 real repos" is dominated by 40.7% of rows pinned at
0.0 by the gate. Among rated repos the variance comes from TTFHR (≈4 samples),
external merge rate, ghost rate (inconsistent windows), downloads percentile
(22% measured), scorecard (62% measured) and EF (login proxy). That is not a
five-pillar signal.

## C. What the composite actually computes today (per pillar) **[DERIVED]**

| Pillar (weight) | Effective input on real data |
|---|---|
| Responsiveness 25 | median of ~4 latencies; external merge rate; ghost rate over a variable window; TTM p90 over the same |
| Criticality 25 | 0.40·100 (all-zero dependents) + 0.35·50 (no signals) + 0.25·downloads percentile (78% zeros) |
| Governance 20 | 0.35·100 (DCO default) + 0.35·min(100, 25·EF_login) + 0.30·40 |
| Rigor 15 | 0.40·(scorecard·10, zero for 38%) + 0.35·40 + 0.25·Gaussian(issue-comment mean) |
| Accessibility 15 | 0.40·0 + 0.35·(100 for 94%) + 0.25·50 |

## D. Answers to the handoff's ten questions

| Q | Answer (decision id in `02`) |
|---|---|
| 1 Missing telemetry | Neither worst-default nor neutral-50. Classify absence (D-MISS-1): third-party gap or collector failure → *unmeasured*, weight renormalised inside the pillar, coverage recorded, tier ceiling by coverage (D-MISS-3); repo-controlled absence (no newcomer labels, no CI, no CONTRIBUTING) → *measured zero*. Taxonomy is persona-independent; coverage is recomputed under persona weights. |
| 2 Bot markers | Use GraphQL `author.__typename == "Bot"` as primary; exact-match list (`[bot]` suffix, named apps) as fallback; substring matching removed (D-IN-1). Universe-wide shift accepted under the v2.0 version bump. |
| 3 Persona gating | One evidence-based `ai_posture`; drop `hard_ai_ban` as a separate input. Persona gates live in a separate `persona_gates` field; `is_stage0_disqualified` stays persona-independent (D-PERS-1). |
| 4 40.7% black holes | Neither publish nor fix yet: recompute with the windowed denominator and the minimum-n rule (D-GATE-5), then publish the corrected rate with its method. Default view excludes gated repos and shows the count. |
| 5 Universe | Freeze the 5,753 minus non-software (manifest check, D-GATE-1) for v2.0; add downloads and dependents top-N criteria at v2.1 (D-UNI). |
| 6 Ground truth | Relational anchors, never pinned numbers (D-VER-4): linux routed off-platform; gcc-mirror gated as mirror; an archived repo gated; an `awesome-*` list excluded; kubernetes and vllm rated with coverage ≥ 0.9 and tier ≥ A; keras-hub's status follows the corrected gate and is reported, not asserted. |
| 7 Validation | Forward outcome experiment (D-VAL): snapshot at T; at T+90 d collect first-timer PRs opened after T; labels = decision within 30 d, merge within 90 d; report Spearman and AUC per pillar and for the composite. |
| 8 Scale | 10k is the v2 ceiling. Persona re-projection moves to SQL anyway because it is linear (D-AGG-4, `04` §6). |
| 9 Deep-dive freshness | Built at promote from the same snapshot, tagged `snapshot_id`; benchmark versions are immutable, so no TTL and no on-demand rebuild. |
| 10 Ship definition | v2.0 = dataset + manifest that reproduces it + API + UI + methodology page. Data quality work dominates the three months; SLA work is done. |
