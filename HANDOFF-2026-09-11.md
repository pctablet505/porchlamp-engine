## 3. Key public API (for whoever wires the API layer / ingestion next)

- `porchlamp.engine.score_repository(meta, pr_events, now, persona=BALANCED,
  ttm_p90_population=None, dependents_population=None, downloads_population=None,
  pillar_scorers=None) -> PorchlampCompositeResult`
  - `pillar_scorers` is a DI seam: dict keyed by pillar name
    (`responsiveness, criticality, governance, rigor, accessibility`); values are
    callables taking the same args as the defaults. Partial dicts allowed.
  - Stage-0 gate failure short-circuits: no pillar called, `overall_porchlamp=0.0`,
    `rank_tier=Tier.D`, `leverage=0.0`, `friction=100.0`, quadrant GRAVEYARD.

  boundary convention: coordinate `>= 50.0` counts as "high" on both axes
  (so `(50.0, 50.0)` → CRUCIBLE). Rounds to 2dp *before* classifying.
- `porchlamp.persona.reproject(pillar_scores, weights) -> float` (raises ValueError if
  weights don't sum to 1.0 within 1e-6 or keys are wrong);
  `persona_composite(pillar_scores, persona)`;
  `rank_deltas(before: list[tuple[str,float]], after: dict[str,float]) -> dict[str,int]`
  (ties broken by position in `before`).
- `porchlamp.lakehouse.OperationalStore(db_path=":memory:")`:
  `.upsert_composite(result, pillar_scores=None, last_indexed_at=None) -> rowid`,
  `.get_repo(owner,name)->dict|None`,
  `.query_matrix(ecosystem=None, quadrant=None, min_stars=0, exclude_black_holes=False, limit=500)`,
  `.leaderboard(ecosystem=None, persona=None, limit=100)`,
  `.count_by_quadrant(ecosystem=None)->dict[str,int]`, `.close()`, `.connection`.
  - Enums stored as `.value` strings; `is_stage0_disqualified` is int 0/1.
  - **`stars` is 0 for every upserted row until ingestion sets it** — so
    `query_matrix(min_stars=100)` (the spec default) returns empty until an
    ingestion layer writes raw metrics. The API layer must ensure ingestion
    populates `stars` before serving matrix queries.

### `tests/test_criticality.py` (7) — root cause: ONE wrong constant, `_SUM_ABS_ALPHA`
The test file hard-codes `_SUM_ABS_ALPHA = 11.5` (line 48) with the comment
`1+1+2+1+1+0.5+0.5+0.5+1+2 = 11.5`. That addition is wrong: the true
`sum(|alpha_i|)` = **10.5** (1+1+2+1+1+0.5+0.5+0.5+1+2 = 10.5). The production
engine (`porchlamp/openssf.py`) correctly computes `sum(abs(a) for a in OPENSSF_WEIGHTS)`
= 10.5. So every hand-computed C in this test file is off by the 11.5-vs-10.5
denominator.

> FIX: change `_SUM_ABS_ALPHA = 11.5` → `10.5` (line 48) and correct the two comment

> recompute each expected C as `sum(alpha_i * S_i*) / 10.5`. Affected tests:

>   (expects 8.5/11.5=0.7391; correct is 8.5/10.5=0.8095)

## 6. Decisions already made (documented in module docstrings — don't relitigate)

- **Quadrant boundary:** coordinate `>= 50.0` = "high" on both axes; round to 2dp before
  classifying. `(50.0,50.0)` → CRUCIBLE.
- **Tier boundary:** `>=` (score exactly at cutoff → higher tier).
- **rank_deltas tie-break:** position in the `before` list (earlier = better rank).
- **Pillar 1 bot-filter:** applied to TTFHR only (spec names it "Bot-Filtered Human
  TTFHR"); MR_first/GR_14/TTM_p90 use the raw external population.
- **Pillar 4 review-depth:** spec prose says "[2.5,4.5] yields >80 pts" but the exact
  Gaussian at the endpoints is ≈80.07; tests assert the exact value, prose treated as
  approximate.
- **Pillar 4 scorecard:** clamped to [0,100] (scorecard 12 must not yield 120).
- **Pillar 2 None signals → 50.0 neutral** (absence of data ≠ low criticality).
- **Lakehouse:** `PorchlampCompositeResult` carries no raw-metric fields, so
  `upsert_composite` stores documented defaults for the spec's NOT NULL raw columns;
  ingestion must update them. `pillar_scores` arg is authoritative over
  `result.pillar_scores`. `count_by_quadrant` always returns all 4 keys.
- **Engine off-platform (gate 3)** is *not* a failure — repo scored normally with
  `stage0.is_off_platform` flagged.
